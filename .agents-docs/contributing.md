# Contributing

## Changelog

`CHANGELOG.md` follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

- **Where**: Add entries under `## [Unreleased]` in the same commit as the change
- **What**: Record changes visible to library users (public API, runtime behavior, types, README docs); leave out tests, tooling, dev dependencies, and internal refactors
- **Sections**: Use only `### Added`, `### Changed`, `### Deprecated`, `### Removed`, `### Fixed`, `### Security`, in that order
- **Breaking changes**: Prefix with `**BREAKING:**`
- **Removals and deprecations**: Name the replacement in parentheses, e.g. `(use the timeout option)`
- **Style**: One line per entry, describing the behavior rather than the implementation
- **Released sections**: Never edit version headings, released entries, or comparison links; the release process manages them
